# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project summary

**Agent Watcher** is a Herdr plugin providing observability for coding agents (Claude Code, Codex, Kimi Code, OpenCode). It watches local agent state and transcripts, reports pane metadata, and sends lifecycle notifications. Single Rust crate (`agent-watcher`, Apache-2.0, edition 2021, **Rust 1.85+ required**). The daemon reconciles Herdr pane state at 1000ms intervals, spawning agent-specific adapters that parse transcripts and status files.

Key constraint: `src/agent/**` is a **frozen port** from the Vimeflow Electron sidecar; legacy protocol identifiers inside it are intentional. Public names (env vars, storage, metadata tokens) use the `agent_watcher_*` namespace. See `PORT-SURFACE.md` for sanctioned modifications and merge rules.

## Common commands

```sh
cargo build                                # debug build
cargo build --release                      # release; install with: herdr plugin link "$PWD" && herdr plugin action invoke restart-daemon --plugin agent-watcher
cargo test                                 # all unit tests + tier-A e2e (regenerates bindings/)
cargo test --test e2e_fake_herdr           # tier A only: deterministic fake Herdr socket
cargo test --test e2e_real_herdr -- --ignored  # tier B: real herdr, isolated HOME/XDG
cargo run --example probe                  # manual live probe against local Herdr socket
./tests/verify-live-agents.sh              # scan live panes for agent_watcher_* tokens (requires live Herdr, jq, nc)
herdr plugin action invoke stop-daemon --plugin agent-watcher  # stop the running daemon
```

## Architecture

**Runtime loop** (`src/daemon/run.rs`):
1. Claim singleton lock, reload Kimi consent if changed
2. Query Herdr over Unix-socket JSON-RPC (3 s timeout)
3. Diff pane list against known bindings → `Bind` / `Unbind` actions, tracking PID/cwd
4. Dispatch through `AgentRegistry` → `SidecarAdapter` → ported watcher pipeline in `src/agent/`
5. Events flow through `EventSink` trait to `HerdrSink` (pane metadata tokens) or `FakeEventSink` (tests)

**Agent adapters** implement the five-method `AgentAdapter` trait (`status_source`, `parse_status`, `validate_transcript`, `tail_transcript`, `agent_type`). Each lives under `src/agent/adapter/<agent>/` with a `StatusSource` declaring `trust_root` for symlink-safe path validation. Supported: `claude_code/`, `codex/`, `kimi/`, `opencode/` (OpenCode also installs a bundled TypeScript bridge plugin).

**Security model**: Every adapter file-read goes through `filesystem::scope::open_nofollow`; transcript paths are canonicalized and re-checked after `create_dir_all` to catch symlink races. Kimi usage consent is disabled by default and requires explicit `kimi-consent` CLI actions.

## Testing strategy

- **Unit tests** live inline in `#[cfg(test)]` modules next to code (e.g., `src/agents/mod.rs`, `src/herdr/client.rs`) or in dedicated sibling files (e.g., `claude_code/transcript_fixture_tests.rs`).
- **Fixtures** (`tests/fixtures/`) are captured from live Herdr 0.8.0 and sanitized with demo identifiers; **never commit live pane/session/filesystem identifiers**. Per-adapter JSONL fixtures live under `src/agent/adapter/<agent>/fixtures/`.
- **Tier A** (`tests/e2e_fake_herdr.rs`): fake Herdr Unix socket, always enabled.
- **Tier B** (`tests/e2e_real_herdr.rs`): real `herdr` binary with isolated HOME/XDG, `#[ignore]`d by default. Note: macOS socket-path length limits — tests use short tempdir prefixes under `/tmp`.
- **TypeScript bindings**: event types in `src/agent/types.rs` and `src/aliases.rs` derive `ts_rs::TS` with `#[cfg_attr(test, ts(export))]`; `cargo test` regenerates `bindings/*.ts`. Preserve these derives when touching event payloads.

## Code style guidelines

- Errors at adapter/service boundaries are `Result<_, String>`; typed `thiserror` enums at wire/client layer (`HerdrClientError`).
- All event emission goes through `Arc<dyn EventSink>` — never print or write directly from adapter/parsing code.
- Parsers use **domain-named helpers** (`bash_command(item)`, `current_usage(value)`) instead of long `.get().and_then(...)` chains. No shared `adapter::json` module — keep JSON path helpers provider-private.
- Parser tolerance: upstream schemas drift, so decode partially and skip unknown lines rather than failing hard.
- **Lifecycle ordering is load-bearing**: `WatcherHandle::Drop` must drop the `notify` watcher *before* signalling/joining the poll thread and stopping the transcript tailer (documented in `src/agent/README.md`). Preserve that order.
- Legacy Vimeflow identifiers inside `src/agent/**` are intentional; do not mass-rename them. New public names use the `agent_watcher_*` namespace (see `PORT-SURFACE.md`).

## Adding a new agent

1. Implement the `AgentAdapter` trait under `src/agent/adapter/<agent>/`.
2. Add the agent ID to `SIDECAR_AGENT_IDS` in `src/agents/sidecar.rs`.
3. Add detection logic in `src/agent/detector.rs`.
4. Agent-specific parsing stays in the adapter; Herdr socket details stay behind the `herdr` module.

## Key constraints

- **Singleton takeover**: the daemon claims an exclusive lock (`daemon/singleton.rs`); only one daemon runs at a time, with a 5 s takeover deadline for CLI commands.
- **Herdr socket**: default `$XDG_CONFIG_HOME/herdr/herdr.sock` (configurable via `HERDR_SOCKET_PATH`). Requests require an object-valued `params` field; 3 s read timeout is load-bearing (must stay below 5 s takeover deadline).
- **Reconciliation interval**: default 1000 ms (`AGENT_WATCHER_INTERVAL_MS`); must be positive. Set in the environment that launches Herdr, then restart the daemon.
- **OpenCode bridge**: first bind installs/updates the bundled TypeScript bridge in OpenCode's plugin directory. Overridable via `AGENT_WATCHER_OPENCODE_PLUGINS_DIR` and `AGENT_WATCHER_OPENCODE_BRIDGE_DIR`.
- **Kimi usage consent**: disabled by default; sends API key to Kimi's `/usages` endpoint only when explicitly enabled via `kimi-consent-on`. Revocation is picked up live without daemon restart.

## Fixtures and sanitization

Live pane IDs, session IDs, and real filesystem paths **must never** be committed to fixtures. Sanitize with deterministic demo identifiers (see `tests/fixtures/README.md`). The verifier script (`tests/verify-live-agents.sh`) redacts pane titles automatically.

## CI

`.github/workflows/ci.yml` runs on every push: `cargo test --all-features`,
`cargo clippy --all-targets --all-features` and `cargo fmt --check`, plus a `portable` job
that runs `cargo check --no-default-features` for the host and for
`x86_64-pc-windows-msvc`.

Clippy is deliberately **not** run with `-D warnings` — the tree carries pre-existing
warnings, and pinning a lint gate to whatever stable ships would re-break CI on every
toolchain bump. It still fails on deny-by-default errors.

`cargo fmt` is enforced, so run it before pushing. Note the local default differs from CI in
two ways: CI passes `--all-features`, and it runs the Windows check.

`.github/workflows/release.yml` runs on `v*` tags and fails if the tag disagrees with
`Cargo.toml`. `herdr-plugin.toml` carries its own version and is checked against `Cargo.toml`
by `tests/cli_keybinding.rs`.
